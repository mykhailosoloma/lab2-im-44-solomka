Код і тести знаходяться в гілці `calculator`:

```bash
git checkout calculator
```

```bash
pytest
```

`pytest` запускає 176 тестів і одразу вимірює покриття коду: прогін вважається невдалим,

## Запуск програми

```bash
python calculator.py examples/input.txt output.txt
```

`examples/input.txt`:

```
1 2 3 + 4 5 6 =
```

Результат `output.txt`:

```
579
```

Якщо не вказати вихідний файл, результат виводиться в консоль: `python calculator.py examples/input.txt`.

## Правила калькулятора

Умова задачі не описує деякі ситуації, тому вони визначені так:

- Дозволений порядок клавіш: цифри → одна операція (`+ - * /`) → цифри → `=`, а також будь-який
  його незавершений початок (`1 2 3 +` показує 123, `1 2 3 + 4` показує 4).
- Будь-який інший порядок — помилка: операція на початку, `=` без операції, `=` одразу після операції,
  дві операції поспіль, ланцюжок `1 + 2 + 3`, будь-яка клавіша після `=`.
- Клавіша — це рівно один символ `0`–`9`, `+`, `-`, `*`, `/` або `=`. Будь-що інше (`12`, `a`, `%`, `.`) — помилка.
- Ділення на нуль — помилка в момент натискання `=` (до цього на екрані просто 0).
- Ділення цілочисельне з округленням вниз (`9 / 1 0 =` → 0). Результат може бути від'ємним (`1 0 - 1 0 0 =` → -90).
- Числа — цілі числа Python (`int`): без переповнення і без втрати точності, як було б із float.
- Клавіші у файлі розділені рівно одним пробілом; перенос рядка в кінці файлу ігнорується.
  Файл може бути в UTF-8 (з BOM або без) чи в UTF-16 (так зберігає `echo ... > file` у Windows PowerShell 5.1).
- При помилці програма пише повідомлення в stderr, завершується з кодом 1 і не створює вихідний файл.

## Що покрито тестами

- **Приклади з умови:** усі 12 рядків таблиці із завдання.
- **Розбір вводу (`parse`):** порожній ввід, розбиття по пробілу, перенос рядка в кінці (LF і CRLF);
  подвійний, початковий чи кінцевий пробіл → `ParseError`.
- **Стан калькулятора (`handle_key_press`):** на початку на екрані 0; кожна цифра як перша і як молодший
  розряд; ведучі нулі; операція запам'ятовує перше число і не змінює екран; перша цифра другого числа
  замінює екран; `=` для кожної операції з правильним порядком операндів (`3 - 7` = -4, `2 / 8` = 0).
- **Невідомі клавіші:** `12`, порожня клавіша, літери, `%`, `.`, `÷`, `+-`, `==`, а також `٣` і `²`
  (для них `str.isdigit()` повертає True, але це не клавіші калькулятора); невідома клавіша
  відхиляється на будь-якому етапі.
- **Заборонені послідовності:** операція на початку, `=` без операції, `=` одразу після операції,
  дві операції поспіль, ланцюжок операцій, цифра, операція чи `=` після `=`.
- **Помилка не псує стан:** після відхиленої клавіші стан калькулятора лишається таким самим, як до неї.
- **Арифметика:** нулі в операндах, множення на 0 і 1, ділення націло, на себе і на 1, округлення вниз
  (1.9 → 1, 9.9 → 9, а не 10), від'ємний результат, великі числа (2⁵³+1 і добуток 10-значних чисел
  рахуються точно, float тут помилився б), результат має тип `int`, а не `float`.
- **Ділення на нуль:** `5 / 0 =`, `0 / 0 =`, `5 / 0 0 =` → `DivisionByZeroError`; без `=` на екрані просто 0.
- **Property-based тести (Hypothesis):** на сотнях випадкових чисел результат збігається з цілочисельною
  арифметикою Python; ділення перевіряється за визначенням округлення вниз (`b·q ≤ a < b·(q+1)`), а не тим
  самим `//`; випадкова послідовність клавіш приймається тоді й лише тоді, коли відповідає регулярному
  виразу дозволеного порядку.
- **Програма (CLI):** запис результату у файл і в консоль, порожній файл → 0, файли в UTF-8 з BOM
  і в UTF-16, повідомлення про помилку з кодом виходу 1 без створення вихідного файлу, відсутній вхідний
  файл, неможливо записати вихідний файл, неправильна кількість аргументів, запуск `python calculator.py`
  окремим процесом.

## Як писались тести

У гілці `calculator` тести з'являються в історії комітів раніше за код: на кожному кроці спочатку
коміт із тестами, що падають (`Add failing tests for ...`), потім коміт із реалізацією, після якої вони проходять.
